FILE 7: src/geospatial/gpci.rs — Phase 2 GPCI algorithm (Novel Method 3)
════════════════════════════════════════════════════════════

Implement the Geospatial Port Congestion Index algorithm:

PortZone struct:
- port_code: String (UN/LOCODE)
- name: String
- anchorage_bbox: BoundingBox  ← lat/lon rectangle
- berth_bbox: BoundingBox
- baseline_wait_times: VecDeque<f64>  ← 90-day rolling

VesselState struct:
- mmsi: u32
- position: (f64, f64)  ← lat, lon
- speed_knots: f64
- heading: f64
- timestamp_ms: u64
- entered_anchorage_at: Option<u64>

Implement fn compute_gpci(port: &PortZone, vessels: &[VesselState]) -> PortCongestionIndex:
1. Filter vessels inside port anchorage_bbox with speed < 2.0 knots (anchored/waiting)
2. Run DBSCAN clustering (epsilon=0.02 degrees, min_samples=3) using rstar R-tree
3. Count anchored_vessel_count from clusters
4. Compute wait_times: for vessels with entered_anchorage_at set, (now - entered) / 3600.0 hours
5. Compute throughput_index: vessels_departed_last_hour / max(vessels_arrived_last_hour, 1)
6. Compute congestion_z_score: (current_wait_median - baseline_median) / baseline_std
7. Normalize to congestion_percentile [0.0, 1.0] using 90-day baseline
Return PortCongestionIndex { port_code, anchored_count, median_wait_hours,
                              throughput_index, congestion_percentile, z_score, timestamp_ms }

════════════════════════════════════════════════════════════

Implement PricePredictionModel(pl.LightningModule):

Architecture:
- input_size: 17 features (full FeatureVector)
- lstm: nn.LSTM(input_size=17, hidden_size=256, num_layers=3, dropout=0.2, batch_first=True)
- attention: nn.MultiheadAttention(embed_dim=256, num_heads=8, dropout=0.1)
- layer_norm: nn.LayerNorm(256)
- fc_direction: nn.Linear(256, 3)     ← [strong_buy, hold, strong_sell]
- fc_magnitude: nn.Linear(256, 1)     ← predicted price change %
- fc_confidence: nn.Linear(256, 1)    ← prediction confidence [0,1]
- dropout: nn.Dropout(0.2)

forward(x: Tensor[batch, seq_len=60, features=17]) -> PredictionOutput:
1. lstm_out, _ = self.lstm(x)          ← [batch, 60, 256]
2. attn_out, attn_weights = self.attention(lstm_out, lstm_out, lstm_out)
3. fused = self.layer_norm(lstm_out + attn_out)   ← residual
4. pooled = fused[:, -1, :]            ← last timestep
5. direction = F.softmax(fc_direction(pooled), dim=-1)
6. magnitude = torch.tanh(fc_magnitude(pooled))
7. confidence = torch.sigmoid(fc_confidence(pooled))
Return PredictionOutput(direction, magnitude, confidence, attn_weights)

Loss: 0.5 * cross_entropy(direction, true_dir) + 0.3 * mse(magnitude, true_mag)
      + 0.2 * bce(confidence, was_correct.float())

Implement training_step, validation_step, configure_optimizers (AdamW, lr=1e-4, cosine schedule)
Implement @classmethod load(path) and save(path)

Implement mc_dropout_inference(x: Tensor, n_samples: int = 100) -> RiskEstimate:
  1. Set all dropout layers to training=True even during eval
  2. Run n_samples forward passes
  3. predictions = stack of n_samples outputs
  4. mean_risk = predictions.mean(dim=0)
  5. uncertainty = predictions.std(dim=0)   ← epistemic uncertainty
  6. Return RiskEstimate(var_95=mean[0], var_99=mean[1], max_drawdown=mean[2],
                         tail_risk=mean[3], uncertainty=uncertainty,
                         high_uncertainty=uncertainty.mean() > threshold)

Position sizing rule: if high_uncertainty → multiply all position sizes by 0.3
                      else → scale by (1 - uncertainty.mean().item())

FILE 14: python/models/nn6_pfcat.py — Phase 2 Cross-Modal Attention (Novel Method 4)
════════════════════════════════════════════════════════════

Implement PhysicalFinancialCrossModalAttention(pl.LightningModule):
This is the PFCAT architecture — the core patent-worthy Phase 2 model.

Architecture:
- market_encoder: nn.Linear(17, 128)      ← encodes microstructure features to Q
- physical_encoder: nn.Linear(8, 128)     ← encodes physical world signals to K,V
- cross_attention: nn.MultiheadAttention(embed_dim=128, num_heads=8, dropout=0.1)
  Q = market_encoder(microstructure)       ← [batch, seq=1, 128]
  K = physical_encoder(physical_sequence) ← [batch, time_steps=48, 128]
  V = physical_encoder(physical_sequence) ← [batch, time_steps=48, 128]
  NOTE: physical_sequence is 48 timesteps of hourly physical data (2-day window)
        market features are current state only
  This architecture lets the model learn: "given current market state,
  which physical world event in the past 48 hours is most relevant?"
- layer_norm: nn.LayerNorm(128)
- fusion_head: nn.Sequential(
    nn.Linear(128 + 17, 256), nn.GELU(), nn.Dropout(0.1),
    nn.Linear(256, 64), nn.GELU(),
    nn.Linear(64, 8)   ← 8-dim physical world signal vector per symbol
  )

forward(microstructure: Tensor[batch, 17],
        physical_history: Tensor[batch, 48, 8]) -> PFCATOutput:
  q = market_encoder(microstructure).unsqueeze(1)    ← [batch, 1, 128]
  k = physical_encoder(physical_history)              ← [batch, 48, 128]
  v = k
  attn_out, attn_weights = cross_attention(q, k, v)  ← attn_weights: [batch, 1, 48]
  attn_out = layer_norm(attn_out.squeeze(1))          ← [batch, 128]
  fused = torch.cat([attn_out, microstructure], dim=-1)
  signal = fusion_head(fused)                         ← [batch, 8]
  lead_lag_profile = attn_weights.squeeze(1)          ← [batch, 48] attention over time
  Return PFCATOutput(signal=signal, lead_lag_profile=lead_lag_profile,
                     peak_lag_hours=lead_lag_profile.argmax(dim=-1))

The lead_lag_profile is THE core novel output — it tells you "physical world event
at T-N hours most influenced today's market state" — learned, not hardcoded.
